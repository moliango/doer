# Mini Program System

## Goal

将现有“插件系统 / 插件 Dock / 插件 Tab”产品形态改造成单论坛场景下的小程序系统。

用户应能在首页通过唯一入口打开小程序抽屉，查看最近使用、我的小程序和分类；能添加网址并自动获取名称与 Logo；能对小程序分类、关闭显示、手动排序。`我的`页面不再展示小程序入口。外观设置中提供全局开关，关闭后首页小程序按钮隐藏，并隐藏小程序相关设置入口，但保留已有小程序数据。

## Confirmed Facts

- 项目永远只做单论坛，不需要多论坛、多账号、小程序 scope 隔离。
- 当前代码已有 `Features/Plugins/MiniProgram/` 原型，包括 `MiniProgramFactory`、`MiniProgramDrawerViewController`、`MiniProgramHostViewController`、`MiniProgramLauncherViewController`、`MiniProgramRecentStore`。
- 当前原型已把 NewAPI 签到和 LD 士多从插件 Tab / Dock 入口迁移到小程序入口方向。
- 当前仍存在插件系统相关用户界面和配置，包括插件中心、插件 Dock 设置、底栏插件配置、`PluginRegistry` / `BuiltInPlugins` 等概念。
- 当前 `我的`页面已经有小程序卡片，但新需求要求只保留首页入口，因此该卡片需要移除。

## Requirements

### Product Model

- App 不再向用户暴露“插件”概念，统一改为“小程序”。
- 小程序系统面向单论坛全局数据，不做 forum/account scope。
- 系统内置小程序包括：
  - LDC
  - CDK
  - NewAPI 签到
  - LD 士多
- 内置小程序不允许删除，但允许关闭显示。
- `LDC`、`CDK`、`NewAPI 签到`、`LD 士多` 都必须出现在小程序管理列表中，统一通过小程序管理控制显示状态。
- 用户自定义网址小程序允许新增、编辑、关闭显示、删除、分类、排序。
- 全局关闭小程序功能时，不删除任何内置或自定义小程序数据。

### Homepage Entry

- 首页是唯一小程序入口。
- 首页保留一个小程序按钮，用于打开小程序抽屉。
- `我的`页面移除小程序卡片和小程序入口。
- 当全局小程序开关关闭时，首页小程序按钮隐藏。

### Mini Program Drawer

- 小程序抽屉展示：
  - 最近使用
  - 我的小程序
  - 分类入口或分类分组
- 最近使用按最后打开时间倒序展示。
- 最近使用只展示当前仍启用显示的小程序。
- 打开任意小程序后，应记录最近使用。
- 抽屉应支持搜索或过滤小程序；如果本期实现成本过高，搜索可以在设计阶段降级为后续项，但 PRD 默认保留。

### Mini Program Management

- 提供小程序管理列表。
- 小程序管理入口复用原“插件管理 / 插件中心”所在位置，入口文案和页面标题改为“小程序”或“小程序管理”。
- 不新增第二套管理入口，避免首页抽屉、设置页、我的页多处重复管理。
- 管理列表支持新增网址小程序。
- 管理列表支持编辑自定义小程序：
  - 名称
  - URL
  - Logo
  - 分类
  - 是否显示
- 管理列表支持关闭显示内置小程序，但不提供删除内置小程序。
- 管理列表支持删除自定义小程序。
- 管理列表必须统一展示内置小程序和用户自定义网址小程序，不能把 `LDC`、`CDK`、`NewAPI 签到`、`LD 士多` 分散在旧插件或其他管理页。
- 管理列表支持手动排序。
- 排序至少支持：
  - 小程序在“我的小程序”中的全局排序
  - 同一分类内的小程序排序
- 用户关闭显示某个小程序后，该小程序不出现在首页抽屉、最近使用、分类列表中。

### URL Mini Program Creation

- 用户输入网址后，系统自动抓取小程序元数据。
- 自动抓取内容包括：
  - 名称：优先站点元数据，其次页面标题，最后域名兜底
  - Logo：优先 `apple-touch-icon` / `icon`，其次 `og:image`，最后默认图标兜底
  - 域名：用于展示来源和去重提示
- 添加页展示安装预览卡，让用户在保存前确认名称、Logo、URL、分类。
- 用户可手动覆盖自动抓取到的名称和 Logo。
- 自定义 Logo 必须支持从本地相册选择图片。
- 自定义 Logo 可继续支持自动抓取图标；本地图片优先级高于自动抓取图标。
- 网络失败、页面无法解析、站点无图标时不能阻塞添加流程，必须提供兜底。

### Categories

- 小程序支持分类。
- 添加网址小程序时可以选择分类。
- 添加网址小程序时可以创建新分类。
- 管理页可以新增、重命名、删除分类。
- 删除分类时，不删除小程序；分类下的小程序应移动到默认分类或“未分类”。
- 分类支持手动排序。
- 初始默认分类建议包括：
  - 工具
  - AI
  - 社区
  - 娱乐
  - 其他

### Appearance Settings

- 外观设置中提供“小程序”全局开关。
- 开关开启时，首页显示小程序按钮，并在原“插件管理 / 插件中心”位置显示小程序管理入口。
- 开关关闭时：
  - 首页小程序按钮隐藏
  - 小程序管理入口隐藏
  - 其他页面不再展示小程序入口
  - 已有小程序数据、分类、排序、最近使用记录保留
- 外观设置里的开关本身必须始终可见，否则用户无法重新开启；隐藏的是小程序相关管理入口，不是这个总开关。

### Me Account Functions

- `我的`页账号功能列表支持用户自定义。
- 用户可以对账号功能入口手动排序。
- 用户可以单独关闭某个账号功能入口，让它不显示在 `我的`页账号功能列表中。
- 账号功能管理入口放在 `我的`页账号功能卡片右上角的“自定义”按钮，直接管理下方列表。
- 账号功能管理不放到设置页，避免用户为了调整当前列表绕远路。
- 默认账号功能包括：消息、网页浏览、AI 模型服务、徽章、信任要求、邀请链接、导出历史、待审内容、Notion 同步、设置。

### Plugin System Removal

- 用户可见层面移除“插件中心”“插件 Dock”“插件 Tab”等概念。
- 原“插件管理 / 插件中心”入口迁移为“小程序管理”，保留位置但更换产品语义。
- 原 `LDC`、`CDK`、`NewAPI 签到`、`LD 士多` 能力迁移为内置小程序或小程序相关能力。
- 底栏配置不再展示插件 Tab 选项。
- Dock 入口不再展示，也不再作为小程序打开方式。
- 如果底层复用部分旧类作为实现细节，不得在文案、设置入口、管理页中暴露“插件”字样。

## Acceptance Criteria

- [ ] 首页存在唯一的小程序入口；点击后打开小程序抽屉。
- [ ] `我的`页面不再展示小程序卡片或小程序入口。
- [ ] 外观设置里存在小程序总开关。
- [ ] 原“插件管理 / 插件中心”位置改为“小程序管理”，不再出现旧插件管理文案。
- [ ] 关闭小程序总开关后，首页按钮隐藏，小程序管理入口隐藏，已保存数据不丢失。
- [ ] 重新开启小程序总开关后，首页按钮恢复，原有小程序、分类、排序仍存在。
- [ ] 小程序抽屉展示最近使用、我的小程序和分类相关内容。
- [ ] 打开小程序会更新最近使用列表。
- [ ] 关闭显示的小程序不会出现在抽屉、最近使用、分类列表中。
- [ ] 内置小程序 `LDC`、`CDK`、`NewAPI 签到`、`LD 士多` 不可删除。
- [ ] 内置小程序可以关闭显示，并可在管理页重新开启。
- [ ] `LDC`、`CDK`、`NewAPI 签到`、`LD 士多` 都出现在小程序管理列表中。
- [ ] 用户可以添加网址小程序。
- [ ] 添加网址时能自动获取名称和 Logo；抓取失败时仍可用域名和默认图标完成添加。
- [ ] 用户可以编辑自定义小程序名称、URL、Logo、分类和显示状态。
- [ ] 用户可以从本地相册选择图片作为自定义小程序 Logo。
- [ ] 用户可以删除自定义小程序。
- [ ] 用户可以创建、重命名、删除、排序分类。
- [ ] 用户可以在分类内手动排序小程序。
- [ ] 删除分类不会删除小程序，分类下小程序会移动到默认分类或未分类。
- [ ] 用户界面不再出现“插件中心”“插件 Dock”“插件 Tab”等旧插件产品入口。
- [ ] 底栏设置不再出现插件 Tab 配置项。
- [ ] 相关持久化具备单论坛全局语义，不使用 forum/account scope 隔离。
- [ ] 现有 NewAPI 签到、LD 士多相关测试继续通过，或按小程序新语义更新测试。
- [ ] `我的`页账号功能列表可以排序和逐项隐藏。
- [ ] 隐藏全部账号功能后，`我的`页账号功能卡片仍保留“自定义”入口，用户可以恢复隐藏项。

## Out Of Scope

- 不做多论坛支持。
- 不做按账号隔离的小程序列表。
- 不做第三方原生插件运行时。
- 不做脚本注入、JS Bridge、离线包、小程序 API 权限系统。
- 不做小程序市场或远程分发。
- 不做 WebView 长驻缓存；默认关闭即销毁，除非后续设计明确需要缓存。

## Open Questions

- `LDC` 和 `CDK` 打开时是否复用现有 Metaverse 服务页面，还是各自拥有独立小程序页面？
- 分类删除后的默认去向使用“其他”还是“未分类”？建议 MVP 使用“其他”，减少新增概念。

## Notes

- 这是复杂任务，不能 PRD-only 直接开工；进入实现前需要补充 `design.md` 和 `implement.md`。
- 重点风险是旧插件系统迁移。实现时必须先理清哪些旧概念要删除、哪些能力只是改名迁移，别半插件半小程序地吊着，后面维护会恶心人。
